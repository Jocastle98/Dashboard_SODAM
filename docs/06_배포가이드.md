## 0. 먼저 알아야 할 것 — 데이터가 사라지는 문제

지금 DB는 SQLite 파일(`data/sodam.db`)이다. 클라우드 호스팅 대부분은 **디스크가 임시**라
재배포하거나 컨테이너가 재시작되면 파일이 사라진다.

**데이터가 사라지면 12개월(389회 요청, 약 7분)을 다시 수집하게 된다.**
남의 운영 서버에 매번 그런 부담을 주는 것은 `CLAUDE.md` POS 배려 규칙에 어긋난다.

그래서 **영속 저장소가 있는 방식만** 선택지에 올린다.

## 1. 선택지

| | 방식 | 월 비용 | 데이터 유지 | 코드 변경 | 슬립 |
|---|---|---|---|---|---|
| **A** | **Fly.io + 볼륨** | **0원** (무료 허용량) | ✅ | 없음 | 없음 |
| B | Render + 영속 디스크 | 약 $7 | ✅ | 없음 | 없음 |
| C | Render 무료 + Supabase Postgres | 0원 | ✅ | **PostgreSQL 이식 필요** | 15분 후 슬립 |
| D | 사장님 PC 상주 실행 | 0원 | ✅ | 없음 | PC를 켜둬야 함 |

### 권장: A (Fly.io)

무료 허용량 안에서 볼륨을 붙일 수 있어 **비용 0원으로 SQLite를 그대로 유지**한다.
코드를 바꿀 필요가 없고 슬립도 없어 새벽 04시 수집이 확실히 돈다.

### C를 고르면 해야 할 일

`docs/02` 6장이 원래 PostgreSQL을 상정했으므로 명세에는 더 맞지만, 이식 작업이 필요하다:

| 대상 | 바꿀 것 |
|---|---|
| `db/schema.sql` | `INTEGER PRIMARY KEY AUTOINCREMENT` → `SERIAL`, `TEXT`(시각) → `TIMESTAMPTZ` |
| `collector/repository.py` | 자리표시자 `?` → `%s`, `sqlite3` → `psycopg` |
| `server/db.py` | 커넥션 풀 |
| `server/repository/sales.py` | `strftime('%w', ...)` → `EXTRACT(DOW FROM ...)` |

UPSERT 문법(`ON CONFLICT ... DO UPDATE`)은 양쪽이 같아 그대로 쓴다.
**반나절 정도 작업이며, 이식 후 12개월 재적재가 한 번 필요하다.**

### D는 언제 쓰나

인터넷 배포 없이 매장 PC에서만 볼 때. `NFR-USE-02`(모바일 필수)를 충족하지 못하므로
공모전 제출용으로는 권장하지 않는다. 다만 백업 경로로는 유효하다.

## 2. 배포 절차 — A (Fly.io)

```bash
# 1) CLI 설치 후 로그인
fly auth login

# 2) 앱 생성 (fly.toml이 이미 있으므로 배포는 미룬다)
fly launch --no-deploy

# 3) 영속 볼륨 — 이게 없으면 데이터가 사라진다
fly volumes create sodam_data --size 1 --region nrt

# 4) 비밀값 등록 (fly.toml에 적지 않는다)
fly secrets set \
  POS_USER_ID='...' \
  POS_USER_PW='...' \
  POS_BRANCH='sodam001' \
  DASHBOARD_ADMIN_ID='...' \
  DASHBOARD_ADMIN_PW='...' \
  SESSION_SECRET="$(python -c 'import secrets;print(secrets.token_urlsafe(48))')"

# 5) 배포
fly deploy

# 6) 대시보드 계정 생성 + 초기 12개월 적재 (한 번만)
fly ssh console -C "python -m server.seed"
fly ssh console -C "python -m collector.main --backfill"

# 7) 확인
fly open
```

## 3. 배포 절차 — B (Render)

1. GitHub에 저장소를 올린다 (`.env`는 `.gitignore`에 있어 올라가지 않는다)
2. Render에서 **New → Blueprint** 선택 후 저장소 연결 → `render.yaml`을 읽는다
3. 대시보드에서 `sync: false`로 표시된 환경변수를 직접 입력한다
4. 배포 후 Shell에서 `python -m server.seed` → `python -m collector.main --backfill`

> `render.yaml`의 `plan: starter`는 영속 디스크 때문이다. `free`로 바꾸면 디스크를 붙일 수 없다.

## 5. 스케줄러

`SCHEDULER_ENABLED=true` 면 웹 서버 프로세스 안에서 매일 `COLLECT_HOUR`시에 전일을 수집한다.

```
매일 04:00 (Asia/Seoul) → 전일 1일치
  주문 1회 + 취소 1회 + 메뉴 1회 = 3요청, 약 3초
```

| 설정 | 의미 |
|---|---|
| `misfire_grace_time=3600` | 서버가 잠깐 죽어 있었어도 1시간 안이면 따라잡는다 |
| `coalesce=True` | 밀린 실행을 한 번으로 합친다 |
| `max_instances=1` | 겹쳐 돌지 않는다 — POS 동시 요청 금지 |

> ⚠ **워커를 2개 이상 띄우면 수집이 중복된다.** 그럴 계획이면
> `SCHEDULER_ENABLED=false`로 두고 `python -m collector.scheduler`를 별도 프로세스로 돌린다.

검증:

```bash
python -m collector.scheduler --once     # 지금 1회 실행
python -m collector.main --status        # 적재 현황
```

## 6. 단일 HTML 내보내기

서버 없이 파일 하나로 여는 스냅샷이다. 시연·제출·백업용.

```bash
python -m server.export --days 30
# → dist/소담촌마곡점_대시보드_2026-08-16.html
```

- CDN·인터넷·서버가 필요 없다 (Chart.js를 인라인한다)
- **자동 갱신되지 않는다.** 만든 시점의 데이터로 고정된다
- 화면 코드는 `web/`을 그대로 재사용한다 — 화면을 두 벌 만들지 않는다
- ⚠ 실제 매출이 들어 있다. `dist/`는 gitignore 대상이며, 파일 전달 시 주의할 것
