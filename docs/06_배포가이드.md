### 채택: E (GitHub Actions + Neon Postgres + Vercel)

| 역할 | 서비스 | 근거 |
|---|---|---|
| 수집 (매일 자동 + 수동 버튼) | **GitHub Actions** | 실행시간 제한 사실상 없음 → 현재 코드 무수정. public 저장소는 분당 과금 없음 |
| 데이터 보관 | **Neon Postgres 무료** | 영구 무료(체험판 아님) + 상업적 이용 허용 + 카드 불필요. 0.5GB 중 사용량 5.5MB |
| 화면 (사장님 접속) | **Vercel Hobby** | git push → 자동 배포. 사장님은 URL 하나만 안다 |

**왜 Vercel 하나로 끝내지 않는가** — Vercel Hobby는 함수가 **10초**에서 끊긴다.
`collector/pos_client.py`의 재시도 백오프(5/15/45초)만 최대 65초라 수집기를 올릴 수 없다.
Hobby 크론도 하루 1회·UTC·시각 오차 1시간이다. 그래서 수집만 GitHub Actions로 뺀다.

**주의 — Vercel Hobby는 상업적 이용 금지.** 약관은 "관련된 누구든 금전적 이익을 목적으로
하는 배포"를 금지한다. 공모전 데모는 허용 예시에 가깝지만 사장님이 영업에 상시 사용하면
회색지대다. 문제가 되면 **Cloudflare Pages**(무료·상업적 이용 명시 허용·git 연동)로 옮긴다.
정적 프론트라 이전 비용이 거의 없다.

### E / C 공통 — PostgreSQL 이식 작업

`docs/02` 6장이 원래 PostgreSQL을 상정했으므로 명세에는 더 맞다.
SQL이 `repository`에만 모여 있어 고칠 파일은 5개다.

| 대상 | 바꿀 것 |
|---|---|
| `db/schema.sql` | `INTEGER PRIMARY KEY AUTOINCREMENT` → `SERIAL`, `TEXT`(시각) → `TIMESTAMPTZ`, `INTEGER`(0/1) → `BOOLEAN`, `datetime('now')` → `NOW()` |
| `collector/repository.py` | 자리표시자 `?` → `%s`, `sqlite3` → `psycopg`, `sqlite3.Row` → `dict_row` (SQL 20문) |
| `collector/service.py` | 타입 힌트 `sqlite3.Connection` 정리 |
| `server/db.py` | 커넥션 풀. Neon은 5분 유휴 시 scale-to-zero → 첫 요청 지연 감안 |
| `server/repository/sales.py` | `strftime('%w', ...)` → `EXTRACT(DOW FROM ...)` — 요일 번호 기준이 달라 확인 필요 (SQL 19문) |

UPSERT 문법(`ON CONFLICT ... DO UPDATE`)은 양쪽이 같아 그대로 쓴다.
**반나절 정도 작업이며, 이식 후 12개월 재적재가 한 번 필요하다** (로컬에서 원격 Neon으로).

### 2-E.1 Neon (완료 — ap-southeast-1 싱가포르, 2026-09-09)

```bash
python -m collector.main --init                                # 스키마 적용
python -m collector.migrate --from sqlite:///./data/sodam.db    # 데이터 이관
python -m collector.migrate --from sqlite:///./data/sodam.db --verify-only
```

**12개월을 다시 수집하지 않는다.** 이미 적재·검증된 데이터를 옮기면 되고,
그러면 POS 요청이 0회다 (「POS 서버 배려」). 이관은 재실행해도 안전하다.

`db/schema_pg.sql` 이 PostgreSQL 판이며 `db/schema.sql`(SQLite)과 **컬럼 구성이 같다.**
어느 쪽을 쓸지는 `DATABASE_URL` 접두사가 결정한다 (`collector/db/dialect.py`).

> `.env` 는 로컬 SQLite 를 가리킨다. Neon 주소는 Vercel·Actions 에 등록할 값이며
> `.env.neon` 에 따로 보관한다(gitignore 대상). 로컬 테스트를 Neon 으로 돌리려면
> `DATABASE_URL` 을 앞에 붙여 실행한다.

### 2-E.2 리전을 맞춰라 — 이게 응답시간을 지배한다

실측 (한국 PC → Neon, 2026-09-08/09):

| | us-east-2 (오하이오) | ap-southeast-1 (싱가포르) |
|---|---|---|
| 커넥션 수립 | 1,541 ms | 803 ms |
| `SELECT 1` 왕복 | 400 ms | **70 ms** |
| `pytest` 126건 | 134 초 | **57 초** |

쿼리 계산이 아니라 **왕복 지연이 전부다.** (SQLite 로컬은 7초)

**중요: 이 느림은 로컬 개발 얘기다.** 배포하면 쿼리가 DB 옆에서 돌아 15ms 수준이 된다.

```
로컬 개발:  내 PC(한국) ──200ms/쿼리──→ Neon                ← 쿼리마다 왕복
배포 후:    브라우저(한국) ──80ms──→ Vercel(sin1) ──5ms──→ Neon(ap-southeast-1)
                                      └ 쿼리는 여기서 돈다
```

위젯들이 병렬로 호출하므로 화면 한 장에 원거리 왕복은 사실상 1회다.

**`vercel.json` 의 `regions` 와 Neon 리전은 반드시 같은 곳이어야 한다.**
채택: **싱가포르 조합** (`sin1` ↔ `ap-southeast-1`) — 2026-09-08 결정.
Neon 은 서울·도쿄 리전을 제공하지 않으므로 한국에서 가장 가까운 선택이다.

#### 왜 서울(icn1)이 아니라 싱가포르(sin1)인가

Vercel 에는 서울 리전 `icn1`(ap-northeast-2) 이 있다. 그런데도 함수를 싱가포르에 둔다.

API 호출 하나가 **DB 를 3회쯤 왕복한다** (예: `/api/summary` = 기간합계 ×2 + 수집이력 ×1).
반면 브라우저→함수 왕복은 위젯들이 병렬로 부르므로 **화면 한 장에 사실상 1회**다.
DB 왕복만 배수로 늘어나므로, 사용자 옆이 아니라 **DB 옆에 두는 것이 이긴다.**

| 조합 | 브라우저→함수 | 함수→DB ×3 | 화면 한 장 |
|---|---|---|---|
| **sin1 + ap-southeast-1** (채택) | ~80 ms | 3 × ~5 ms | **~95 ms** |
| icn1(서울) + ap-southeast-1 | ~10 ms | 3 × ~70 ms | ~220 ms |
| iad1 + us-east-2 | ~180 ms | 3 × ~15 ms | ~225 ms |
| sin1 + us-east-2 | ~80 ms | 3 × ~230 ms | **~770 ms** ← 한쪽만 바꾼 결과 |

Neon 은 서울 리전을 제공하지 않으므로 싱가포르가 한국에서 가장 가까운 DB 위치다.

> ✅ **Hobby 플랜도 단일 리전 지정은 된다** (2026-09-09 문서 확인).
> Vercel 문서 Limits: `Hobby = Single region` / `Pro = 5` / `Enterprise = All`.
> 제한은 **복수** 리전에만 걸린다. 우리는 `["sin1"]` 하나이므로 배포가 거부되지 않는다.
> 다만 플랜보다 많은 리전을 넣으면 **빌드 이전 단계에서 배포가 실패**한다 — 늘리지 말 것.

#### 정적 파일은 함수까지 보내지 않는다

함수가 싱가포르에 있으므로, JS·CSS 를 함수로 보내면 파일마다 싱가포르를 왕복한다.
`vercel.json` 의 `/(js|css)/(.*)` 헤더가 `s-maxage` 로 CDN 캐시를 허용해
사용자 근처 PoP 에서 나가게 한다. 브라우저는 `max-age=0` 으로 매번 확인하므로
배포 후 옛 화면이 남지 않는다 (Vercel 이 배포 시 CDN 캐시를 비운다).

**리전 이전 절차** (Neon 은 기존 프로젝트의 리전을 바꿀 수 없다 — 새로 만들어야 한다):

```bash
# 1) Neon 콘솔에서 새 프로젝트 생성 — Region: AWS Asia Pacific (Singapore) ap-southeast-1
# 2) 새 연결 문자열을 .env.neon 에 반영
# 3) 스키마 + 데이터 (POS 요청 0회)
DATABASE_URL="$(grep -m1 ^DATABASE_URL= .env.neon | cut -d= -f2-)" python -m collector.main --init
python -m collector.migrate --from sqlite:///./data/sodam.db --to "$(grep -m1 ^DATABASE_URL= .env.neon | cut -d= -f2-)"
python -m collector.migrate --from sqlite:///./data/sodam.db --to "..." --verify-only
```

**원본은 로컬 `data/sodam.db` 다.** 기존 Neon 프로젝트를 지워도 데이터를 잃지 않는다.
Vercel·Actions 에 등록한 `DATABASE_URL` 은 함께 갱신해야 한다.

### 2-E.3 Vercel (배포 완료 — 2026-09-09)

```
https://sodam-dashboard.vercel.app      (프로젝트: sodam5/sodam-dashboard)
```

실측 (한국에서):

| | 시간 |
|---|---|
| API 7개, 병렬 호출 → 화면 체감 | **~166 ms** |
| `/js/dashboard.js` (CDN HIT) | 27 ms |
| Chart.js 205KB (CDN HIT) | 55 ms |
| 로그인 (첫 호출, 콜드스타트 포함) | 457 ms |

리전 확인: 응답 헤더 `X-Vercel-Id: icn1::sin1::...`
→ 요청은 **서울 PoP(icn1)** 로 들어오고 함수는 **싱가포르(sin1)** 에서 돈다. 의도대로다.
정적 파일은 `X-Vercel-Cache: MISS → HIT` 로 서울 PoP 에서 나간다.

#### ⚠ vercel.json 에 주석을 넣을 수 없다

Vercel 은 이 파일의 스키마를 엄격히 검증한다. `"//"` 키는 **최상단에도** 넣을 수 없다
(`vercel link` 는 통과하지만 `vercel deploy` 가 `should NOT have additional property '//'`
로 거부한다). **설정 근거는 이 문서에만 둔다.**

#### FastAPI 는 `services` 로 잡힌다

Vercel 이 FastAPI 를 감지하면 `services` 모델로 처리한다. 그래서:

- 최상단 `functions` 를 쓸 수 없다 (`owning service is ambiguous` 오류)
- 서비스에 `entrypoint` 가 필요하다 — `"server.main:app"` (모듈:속성 형식)
- `rewrites` / `headers` 는 최상단에, 빌드·런타임 설정은 서비스 안에 둔다

현재 설정:

```json
{
  "regions": ["sin1"],
  "services": { "dashboard": { "root": ".", "entrypoint": "server.main:app" } },
  "rewrites": [{ "source": "/(.*)", "destination": { "service": "dashboard" } }]
}
```

`api/index.py` 는 이 경로에서 쓰이지 않는다 — Vercel 이 `server.main:app` 을 직접 실행한다.
자체 호스팅이나 다른 PaaS 로 옮길 때를 위해 남겨 둔다.

배포 전 점검은 자동화돼 있지 않다. 아래를 눈으로 확인할 것:

| 확인 | 왜 |
|---|---|
| `vercel.json` 의 `regions` 가 **하나** | Hobby 는 단일 리전. 더 넣으면 빌드 전에 실패 |
| `regions` 가 Neon 리전과 같은 곳 | 어긋나면 왕복 지연이 3배 이상 늘어난다 |
| 배포 후 함수 로그의 리전 | 실제로 `sin1` 에 떴는지 |
| `POS_*` / `SCHEDULER_ENABLED` 미등록 | 위 표 참고 |

환경변수 (Vercel 대시보드 → Settings → Environment Variables):

| 이름 | 값 | 비고 |
|---|---|---|
| `DATABASE_URL` | Neon 주소 | 읽기 |
| `SESSION_SECRET` | 랜덤 문자열 | `.env` 와 같은 값이어야 기존 세션이 유지된다 |
| `STORE_CODE` / `STORE_NAME` | | |
| `DISPATCH_REPO` / `DISPATCH_TOKEN` | 5-2장 참고 | 지금 수집 버튼용 |
| ~~`POS_USER_ID` / `POS_USER_PW`~~ | **넣지 않는다** | 화면 쪽이 POS 계정을 들 이유가 없다 |
| ~~`SCHEDULER_ENABLED`~~ | **넣지 않는다** | 서버리스에는 상주 프로세스가 없다. `true` 면 함수가 APScheduler 와 POS 클라이언트를 적재한다 |

> `.env` 를 그대로 복사하지 말 것. 로컬 `.env` 에는 `SCHEDULER_ENABLED=true` 와
> POS 계정이 들어 있다. **필요한 것만 골라 넣는다.**

`SESSION_COOKIE_SECURE` 는 **지정하지 않아도 된다** — Vercel 이 주는 `VERCEL` 환경변수를
보고 자동으로 켜진다 (`collector/config.py`). 깜빡해서 세션 쿠키가 평문으로 오가는
일을 막기 위한 기본값이다 (NFR-SEC-01).

### 2-E.4 GitHub Actions (검증 완료 — 2026-09-09)

첫 실행: `workflow_dispatch`, 42초, 성공. 주문 26건 / 메뉴 32행 / 취소 3건.

**⚠ 워크플로가 `main`(기본 브랜치)에 있어야 한다.** `v1.0.x` 브랜치에만 있으면
GitHub 이 워크플로를 **아예 인식하지 않는다** (`/actions/workflows` → `total_count: 0`).
그 상태에서 Actions 화면을 열면 워크플로 대신 템플릿 목록이 나오는데, 거기서
아무것도 고르면 안 된다 — 우리 워크플로는 이미 있고 병합만 필요하다.

`schedule` 은 기본 브랜치 전용이라는 GitHub 규칙 때문이며 우회할 수 없다.

**`TZ: Asia/Seoul` 이 실제로 필요했다.** 첫 실행에서 수집 대상이 `20260908`
(KST 기준 전일)로 정확히 나왔다. TZ 를 안 걸면 러너가 UTC 라 `date.today()` 가
하루 이전을 가리켜 `20260907` 을 수집한다 — 조용히 하루씩 밀린다.

**요금은 0원이다.** GitHub 공식 문서: *"GitHub Actions usage is free for
self-hosted runners and for public repositories that use standard GitHub-hosted runners."*
`runs-on: ubuntu-latest` 는 기본 러너이므로 분 제한 없이 무료다. 결제수단도 필요 없다.
private 으로 바꾸면 Free 플랜 월 2,000분 한도가 적용된다 (우리 수집은 월 60분 수준).

### 2-E.4-b 설정 목록

목록과 주의사항(60일 무활동 시 schedule 자동 정지, `TZ: Asia/Seoul` 이 필요한 이유)은

## 5-2. 수동 수집 버튼 (FN-205 / FR-COL-07)

화면의 **지금 수집** 버튼이 무엇을 깨우는지는 환경에 따라 다르다.
판단은 `server/collect_trigger.py` 한 곳에서만 한다.

| 백엔드 | 조건 | 동작 | 어디서 쓰나 |
|---|---|---|---|
| `local` | `POS_USER_ID` / `POS_USER_PW` | 이 프로세스가 백그라운드 스레드로 직접 수집 | 내 PC·자체 서버 |
| `github` | `DISPATCH_REPO` / `DISPATCH_TOKEN` | Actions `workflow_dispatch` 호출 | **Vercel 배포** |
| `none` | 둘 다 없음 | 버튼을 숨긴다 | — |

### 왜 Vercel이 직접 수집하지 않는가

두 가지 이유가 있고 둘 다 우회할 수 없다.

1. **Vercel Hobby 함수는 10초에서 끊긴다.** `pos_client.py`의 재시도 백오프
   (5/15/45초)만 최대 65초다. 수집 자체도 30초~1분 걸린다.
2. **Vercel에는 POS 계정을 올리지 않는다.** 사장님이 접속하는 쪽이 POS 계정을
   들 이유가 없다 (CLAUDE.md 「POS 접근은 오직 `collector/` 안에서만」의 배포판).

그래서 Vercel은 "수집해달라"고 부탁만 하고 빠진다. 실제 수집은 Actions가 한다.

### 설정

**1) PAT 발급** — GitHub → Settings → Developer settings → Personal access tokens
→ Fine-grained token. 권한은 **해당 저장소의 Actions: Read and write 하나만.**
`contents`나 `secrets` 권한은 주지 않는다.

**2) Vercel 환경변수**

| 이름 | 값 |
|---|---|
| `DISPATCH_REPO` | `소유자/저장소` |
| `DISPATCH_TOKEN` | 위에서 발급한 PAT |
| `DISPATCH_WORKFLOW` | `collect.yml` (기본값이라 생략 가능) |
| `DISPATCH_REF` | `main` (기본값이라 생략 가능) |

> 이름에 `GITHUB_` 접두사를 쓰지 않는다. Actions가 `GITHUB_*`를 예약해 쓰고
> `GITHUB_REF_NAME` 같은 값은 워크플로 안에서 자동으로 덮어써진다.

**3) GitHub Actions Secrets** — `.github/workflows/collect.yml`이 쓰는 값:
`POS_USER_ID`, `POS_USER_PW`, `POS_BRANCH`, `POS_LANDING_URL`,
`DATABASE_URL`, `STORE_CODE`, `STORE_NAME`, `ALERT_WEBHOOK_URL`.

### POS 서버 배려 — 버튼이 규칙을 깨지 않게

| 장치 | 근거 |
|---|---|
| 동시 실행 금지 | `local`은 스레드 락, `github`은 워크플로 `concurrency: collect` |
| 최소 간격 10분 | `MANUAL_COLLECT_MIN_INTERVAL_SEC`. 넘기면 `429 TOO_SOON` + `Retry-After` |
| 실패도 간격에 포함 | 마지막 **시도** 시각 기준. 성공만 보면 실패가 반복될 때 계속 두드린다 |
| 화면 차단 | 수집 중·대기 중에는 버튼 비활성 |

`local`의 최소 간격은 DB의 `collection_logs`와 프로세스 메모리를 **둘 다** 본다.
로그인 단계에서 실패하면 `collection_logs`에 행이 아예 안 남기 때문이다.

### ⚠ Actions 스케줄이 60일 후 자동으로 멈춘다

GitHub은 **저장소에 60일간 활동이 없으면 `schedule` 트리거를 비활성화**한다.
자동 수집이 조용히 끊기고, 배지가 ● 수집 실패로 바뀌는 것 말고는 알림이 없다.

되살리는 방법:
- 대시보드의 **지금 수집** 버튼을 누른다 (`workflow_dispatch`는 정지되지 않는다), 또는
- 저장소에 커밋을 하나 넣는다, 또는
- Actions 화면의 재활성화 버튼을 누른다

정기 점검 항목이다 (7장 참고).

## 6. 파일 하나로 전달하기 — 두 가지 방식

목적이 정반대인 산출물이 둘 있다. 섞지 말 것.

| | `server/shortcut.py` | `server/export.py` |
|---|---|---|
| 만드는 것 | 배포 대시보드로 보내는 바로가기 | 데이터를 박아 넣은 스냅샷 |
| 갱신 | ✅ **항상 최신** | ❌ 만든 시점 고정 |
| 인터넷 | 필요 | 불필요 |
| 파일 안의 매출 | **없음** (주소만) | 있음 |
| 용도 | 사장님 상시 사용 | 시연·공모전 제출·백업 |

### 6.1 바로가기 HTML — 사장님께 전달할 것

```bash
# .env 에 DASHBOARD_URL=https://<배포주소> 를 넣고
python -m server.shortcut
# → dist/소담촌마곡점_대시보드_바로가기.html
```

더블클릭하면 브라우저가 열리며 대시보드로 이동한다. **화면은 항상 최신이다** —
매일 04시 자동 수집 + 지금 수집 버튼이 데이터를 채우고, 파일은 그것을 보여주는 창구다.

파일에 매출 수치가 한 글자도 없으므로 전달·보관에 제약이 없다.

> **왜 파일이 스스로 POS에서 받아올 수 없는가.** 브라우저는 topint.co.kr에 직접
> 요청할 수 없다 — CORS로 막히고, 뚫어도 POS 계정이 파일에 노출된다. 갱신하는
> 주체는 반드시 서버여야 하므로 "파일 하나 + 항상 최신"의 유일한 길은
> 파일이 그 서버를 가리키는 것이다. **오프라인 + 최신 조합은 어떤 방식으로도 불가능하다.**

### 6.2 단일 HTML 스냅샷 — 시연·제출용

서버 없이 파일 하나로 여는 스냅샷이다.

```bash
python -m server.export --days 30
# → dist/소담촌마곡점_대시보드_2026-08-16.html
```

- CDN·인터넷·서버가 필요 없다 (Chart.js를 인라인한다)
- **자동 갱신되지 않는다.** 만든 시점의 데이터로 고정된다
- 화면 코드는 `web/`을 그대로 재사용한다 — 화면을 두 벌 만들지 않는다
- 로그아웃·기간 필터·지금 수집 버튼은 서버가 필요하므로 제거된다
- ⚠ 실제 매출이 들어 있다. `dist/`는 gitignore 대상이며, 파일 전달 시 주의할 것

서버 없이 파일 하나로 여는 스냅샷이다. 시연·제출·백업용.

