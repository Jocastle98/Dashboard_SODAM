## 1. 시스템 구성 요소

| 구성요소 | 역할 | 기술 스택(제안) |
|---|---|---|
| **F-01 Dashboard UI** | 로그인 + 데이터 시각화 | HTML / CSS / JS (또는 React) + Chart.js |
| **F-02 Auth Service** | 대시보드 사용자 인증·세션 | Node.js(Express) 또는 Python(FastAPI) |
| **F-03 Data API** | 집계 데이터 조회 REST API | 동상 |
| **F-04 Collector** | POS 데이터 수집·정제·적재 | Python (requests / pandas) |
| **F-05 Scheduler** | 수집 정기 실행 | cron / APScheduler |
| **F-06 Database** | 원본·집계 데이터 저장 | PostgreSQL 또는 SQLite(소규모) |

> 무료/저비용 구성 예시: Frontend → Vercel, Backend+Scheduler → Render, DB → Supabase(PostgreSQL)

**② KPI 카드 (FN-210)**
| 카드 | 계산식 | 비교 기준 |
|---|---|---|
| 총 매출 | `SUM(sales_amount)` | 직전 동일 길이 기간 |
| 결제건수 | `SUM(order_count)` | 동상 |
| 객단가 | `총매출 ÷ 결제건수` | 동상 |
| 일평균 매출 | `총매출 ÷ 영업일수` | 동상 (휴무일 제외) |

- 증감률 = `(현재 − 이전) ÷ 이전 × 100`, 소수 1자리
- 이전 기간 데이터 없으면 "비교 데이터 없음" 표시
- 증감 표기: ▲ 상승 / ▼ 하락 / — 변화없음 + 색상 병기

| 항목 | 사양 |

**④ 요일별 평균 매출 (FN-230)**

## 4. 데이터 수집 기능 상세 (F-04 Collector)

### 4.1 처리 흐름
```
[시작]
   ↓
① 대상 기간 결정 (기본: 전일 / 파라미터 지정 가능)
   ↓
② POS 인증 (시크릿에서 계정 로드)
   ↓ 실패 → 재시도(3회, 지수 백오프) → 최종 실패 시 알림 후 종료
③ 일별 매출 데이터 조회
   ↓
④ 메뉴별 판매 데이터 조회
   ↓
⑤ 시간대별 데이터 조회
   ↓
⑥ 정제: 타입 변환, 숫자 콤마 제거, 날짜 표준화(YYYY-MM-DD), 메뉴명 공백 정리
   ↓
⑦ 검증: DQ-01~04 규칙 적용 → 위반 시 경고 로그
   ↓
⑧ DB UPSERT (raw + 집계 테이블)
   ↓
⑨ 수집 로그 기록
   ↓
[종료]
```

### 4.2 수집기 상세 규칙
| 기능ID | 기능명 | 동작 |
|---|---|---|
| FN-601 | 스케줄 실행 | 매일 04:00 KST 자동 실행 |
| FN-602 | 초기 적재 | 최초 1회 과거 12개월 일괄 수집 (일 단위 순회, 요청 간 1초 대기) |
| FN-603 | 재시도 | 네트워크/타임아웃 오류 시 3회, 5s/15s/45s 간격 |
| FN-604 | 멱등성 | 동일 (매장, 일자) 키에 대해 UPSERT — 중복 저장 금지 |
| FN-605 | 부하 배려 | 초당 1건 이하 요청, User-Agent 명시 |
| FN-606 | 실패 알림 | 최종 실패 시 이메일/메신저 발송 |
| FN-607 | 원본 보존 | 파싱 전 원본 응답을 raw 테이블에 저장 (재처리 대비) |

## 5. API 명세

> Base URL: `https://{domain}/api`
> 인증: HttpOnly 세션 쿠키. 미인증 시 `401`

### 5.1 인증

#### `POST /api/auth/login`
```jsonc
// Request
{ "username": "sodam001", "password": "********", "remember": false }

// 200 OK
{ "success": true, "user": { "username": "sodam001", "storeName": "소담촌 마곡점" } }

// 401
{ "success": false, "error": { "code": "AUTH_FAILED", "message": "아이디 또는 비밀번호가 올바르지 않습니다." } }

// 429
{ "success": false, "error": { "code": "TOO_MANY_ATTEMPTS", "message": "5분 후 다시 시도해주세요.", "retryAfter": 300 } }
```

#### `POST /api/auth/logout` → `200 { "success": true }`
#### `GET /api/auth/session` → `200 { "authenticated": true, "user": {...} }`

### 5.2 데이터 조회

#### `GET /api/summary?from=2026-07-01&to=2026-07-31`
```jsonc
{
  "period": { "from": "2026-07-01", "to": "2026-07-31", "businessDays": 27 },
  "current": { "totalSales": 12340000, "orderCount": 1204, "avgTicket": 10249, "dailyAvg": 457037 },
  "previous": { "totalSales": 11405000, "orderCount": 1168, "avgTicket": 9765, "dailyAvg": 422407 },
  "change": { "totalSales": 8.2, "orderCount": 3.1, "avgTicket": 5.0, "dailyAvg": 8.2 },
  "lastUpdated": "2026-08-16T04:12:00+09:00"
}
```

#### `GET /api/sales/daily?from=&to=`
```jsonc
{
  "data": [
    { "date": "2026-07-01", "dayOfWeek": "화", "sales": 421000, "orders": 41, "avgTicket": 10268, "isClosed": false },
    { "date": "2026-07-02", "dayOfWeek": "수", "sales": null, "orders": null, "avgTicket": null, "isClosed": true }
  ]
}
```
> `sales: null` + `isClosed: true` → 휴무 / `sales: null` + `isClosed: false` → 미수집

#### `GET /api/sales/weekday?from=&to=`
```jsonc
{ "data": [ { "dayOfWeek": "월", "avgSales": 380000, "avgOrders": 37, "sampleDays": 4 } ] }
```

#### `GET /api/sales/hourly?from=&to=`
```jsonc
{
  "available": true,
  "data": [ { "hour": 11, "sales": 210000, "orders": 20 }, { "hour": 12, "sales": 880000, "orders": 82 } ],
  "peakHours": [12, 18, 19]
}
```

#### `GET /api/menu/ranking?from=&to=&limit=10&sortBy=sales`
```jsonc
{
  "totalSales": 12340000,
  "data": [
    { "rank": 1, "menuCode": "M001", "menuName": "소담 샤브 정식", "category": "샤브세트",
      "quantity": 412, "sales": 4120000, "share": 33.4, "abcGrade": "A", "rankChange": 0 }
  ]
}
```

#### `GET /api/menu/{menuCode}/trend?from=&to=`
```jsonc
{ "menuName": "소담 샤브 정식", "data": [ { "date": "2026-07-01", "quantity": 14, "sales": 140000 } ] }
```

#### `GET /api/system/status`
```jsonc
{ "lastCollectedAt": "2026-08-16T04:12:00+09:00", "lastCollectedDate": "2026-08-15",
  "status": "ok", "dataRange": { "from": "2025-08-01", "to": "2026-08-15" } }
```
> `status`: `ok` | `delayed` | `failed`

### 5.3 공통 오류 응답

| 404 | `NOT_FOUND` | 데이터를 찾을 수 없습니다. |

## 6. 데이터베이스 스키마

```sql
-- 매장
CREATE TABLE stores (
  store_id      SERIAL PRIMARY KEY,
  store_code    VARCHAR(50) UNIQUE NOT NULL,   -- 'SODAM_MAGOK'
  store_name    VARCHAR(100) NOT NULL,         -- '소담촌 마곡점'
  open_hour     SMALLINT DEFAULT 11,
  close_hour    SMALLINT DEFAULT 22,
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

-- 대시보드 사용자 (POS 계정과 분리)
CREATE TABLE users (
  user_id       SERIAL PRIMARY KEY,
  store_id      INT REFERENCES stores(store_id),
  username      VARCHAR(50) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,         -- bcrypt
  role          VARCHAR(20) DEFAULT 'owner',   -- owner | manager | admin
  last_login_at TIMESTAMPTZ,
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

-- 일별 매출
CREATE TABLE daily_sales (
  store_id      INT REFERENCES stores(store_id),
  biz_date      DATE NOT NULL,
  sales_amount  BIGINT,
  order_count   INT,
  discount_amt  BIGINT DEFAULT 0,
  cancel_amt    BIGINT DEFAULT 0,
  is_closed     BOOLEAN DEFAULT FALSE,
  updated_at    TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (store_id, biz_date)
);

-- 메뉴 마스터
CREATE TABLE menus (
  menu_id       SERIAL PRIMARY KEY,
  store_id      INT REFERENCES stores(store_id),
  menu_code     VARCHAR(50) NOT NULL,
  menu_name     VARCHAR(200) NOT NULL,
  category      VARCHAR(50),
  unit_price    INT,
  is_active     BOOLEAN DEFAULT TRUE,
  UNIQUE (store_id, menu_code)
);

-- 메뉴별 일 판매
CREATE TABLE menu_sales (
  store_id      INT,
  biz_date      DATE,
  menu_id       INT REFERENCES menus(menu_id),
  quantity      INT,
  sales_amount  BIGINT,
  PRIMARY KEY (store_id, biz_date, menu_id)
);

-- 시간대별 매출
CREATE TABLE hourly_sales (
  store_id      INT,
  biz_date      DATE,
  hour          SMALLINT CHECK (hour BETWEEN 0 AND 23),
  sales_amount  BIGINT,
  order_count   INT,
  PRIMARY KEY (store_id, biz_date, hour)
);

-- 수집 로그
CREATE TABLE collection_logs (
  log_id        SERIAL PRIMARY KEY,
  store_id      INT,
  started_at    TIMESTAMPTZ,
  finished_at   TIMESTAMPTZ,
  target_from   DATE,
  target_to     DATE,
  status        VARCHAR(20),      -- success | partial | failed
  record_count  INT,
  error_message TEXT
);

-- 원본 보존
CREATE TABLE raw_payloads (
  raw_id        BIGSERIAL PRIMARY KEY,
  store_id      INT,
  biz_date      DATE,
  source_type   VARCHAR(50),      -- daily | menu | hourly
  payload       JSONB,
  collected_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_daily_date  ON daily_sales(store_id, biz_date DESC);
CREATE INDEX idx_menu_date   ON menu_sales(store_id, biz_date DESC);
CREATE INDEX idx_hourly_date ON hourly_sales(store_id, biz_date DESC);
```

## 7. 주요 시퀀스

### 7.1 로그인 → 대시보드 진입
```
사용자        Dashboard UI       Auth API         DB
  │                │                │              │
  ├─ URL 접속 ────►│                │              │
  │                ├─ GET /auth/session ──────────►│
  │                │◄── 401 미인증 ─────────────────┤
  │◄─ 로그인 화면 ──┤                │              │
  ├─ ID/PW 입력 ──►│                │              │
  │                ├─ POST /auth/login ───────────►│
  │                │                ├─ 사용자 조회 ►│
  │                │                │◄─ hash ──────┤
  │                │                ├─ bcrypt 검증 │
  │                │◄── 200 + 세션쿠키 ─────────────┤
  │◄─ 대시보드 ────┤                │              │
```

### 7.2 대시보드 데이터 로드 (병렬)
```
Dashboard UI ─┬─► GET /api/summary        ─┐
              ├─► GET /api/sales/daily    ─┤
              ├─► GET /api/sales/weekday  ─┼─► Data API ─► DB(집계 조회)
              ├─► GET /api/sales/hourly   ─┤
              ├─► GET /api/menu/ranking   ─┤
              └─► GET /api/system/status  ─┘
                  (응답 도착 순으로 위젯 개별 렌더링)
```

### 7.3 일일 자동 수집
```
Scheduler ─(04:00)─► Collector ─► POS 로그인 ─► 데이터 조회
                          │                        │
                          │◄───────────────────────┘
                          ├─► 정제/검증
                          ├─► DB UPSERT
                          └─► collection_logs 기록
                                    │
                              실패 시 └─► 알림 발송
```
