## 1. 왜 CLAUDE.md를 루트에 두는가

Claude Code는 세션 시작 시 루트의 `CLAUDE.md`를 **자동으로 읽습니다.** 명세서를 매번 붙여넣을 필요가 없고, 대화가 길어져 컨텍스트가 밀려나도 규칙이 유지됩니다.

특히 이 프로젝트에서 반복적으로 틀릴 수 있는 것들 — **euc-kr 인코딩, .xls가 실제로는 HTML, 프론트에서 POS 직접 호출 금지, 계정 하드코딩 금지** — 을 CLAUDE.md에 못박아 두었기 때문에 매 세션 같은 실수를 다시 설명하지 않아도 됩니다.

명세서 본문은 분량이 커서 CLAUDE.md에 넣지 않고 `docs/`에 두고 **경로만 참조**했습니다. Claude Code가 필요할 때 직접 열어봅니다.

### STEP 3 — 스키마 + 수집 파이프라인 + 초기 적재

```
docs/02의 6장 DB 스키마와 docs/03의 실측 컬럼을 대조해줘.
실제 POS 컬럼과 스키마가 맞지 않는 부분이 있으면 먼저 알려주고,

- collector/main.py — 기간 인자를 받아 수집~적재를 실행하는 진입점
- 파서 단위 테스트 — data/에 저장된 실제 응답 파일을 픽스처로 사용
```

## 4. 공모전 관점 보완 (Phase 1 완료 후)

기능이 다 돌아간 뒤 여유가 있으면 이 순서로 얹는 게 심사 점수에 효율적입니다.

| 우선 | 항목 | 근거 |
|---|---|---|
| 1 | 요일×시간대 히트맵 | 인력 배치라는 실제 의사결정에 직결. 시각적 임팩트도 큼 |
| 2 | 메뉴 ABC 분석 | 메뉴 정리·가격 조정 근거. 데이터가 이미 있음 |
| 3 | 7일 이동평균 + 이상치 표시 | "왜 이날 매출이 튀었나"를 사장님이 스스로 묻게 만듦 |
| 4 | 날씨 데이터 결합 | 외부 데이터 활용 = 빅데이터 공모전 가점 요소. 기상청 API 무료 |
| 5 | 익일 매출 예측 | Prophet 또는 단순 회귀. 데이터 12개월이면 시도 가능 |

4~5번은 **1~3번이 완성된 뒤에** 붙이세요. 예측 모델이 화려해도 기본 대시보드가 덜 됐으면 실효성 점수에서 깎입니다.
