# 소담촌 마곡점 매출 대시보드 — 요구사항명세서 (SRS)

| 항목 | 내용 |
|---|---|
| 문서명 | 샤브샤브 소담촌 마곡점 매출 분석 대시보드 요구사항명세서 |
| 버전 | v0.1 (Phase 0~1 범위) |
| 작성일 | 2026-08-16 |
| 프로젝트 | 소상공인 매출증대 AI 빅데이터 공모전 |

---

## 1. 개요

### 1.1 목적
마곡점 사장님이 **URL 하나로 접속하여 매일 갱신되는 매출·메뉴 데이터를 시각적으로 확인**할 수 있는 웹 대시보드를 구축한다. 본 문서는 그 구현을 위한 요구사항을 정의한다.

### 1.2 범위
| 단계 | 범위 | 본 문서 대상 |
|---|---|---|
| **Phase 0** | POS 데이터 구조 파악, 접근 방식 확정 | ✅ |
| **Phase 1** | 로그인 → 데이터 연동 → 시계열 대시보드 표시 | ✅ |
| Phase 2 | AI 수요예측, 메뉴 추천, 발주 최적화 | ❌ (차기) |
| Phase 3 | 상권/외부데이터 결합 분석 | ❌ (차기) |

### 1.3 용어 정의
| 용어 | 정의 |
|---|---|
| POS | (주)탑아이앤티가 제공하는 매장 판매시점관리 시스템 (topint.co.kr) |
| 수집기(Collector) | POS에서 데이터를 주기적으로 가져오는 서버 모듈 |
| 대시보드 | 사장님이 접속하는 웹 화면 |
| 객단가 | 매출액 ÷ 결제건수 |
| ABC 분석 | 매출 기여도 기준 메뉴 등급 분류 (A: 상위 70%, B: ~90%, C: 나머지) |

## 2. 시스템 구성 및 핵심 제약

### 2.1 ⚠️ 반드시 먼저 확인해야 할 기술 제약

**"HTML 파일 하나에서 topint.co.kr에 직접 로그인하여 데이터를 가져오는 것"은 불가능하다.**

| 제약 | 사유 |
|---|---|
| CORS 정책 | 브라우저는 topint.co.kr이 명시적으로 허용하지 않는 한, 외부 도메인 스크립트의 요청을 차단한다. |
| 세션/인증 | POS는 서버 세션 기반 로그인이므로 클라이언트 단독으로 세션 유지가 불가하다. |
| 보안 | 사장님 계정 정보를 프론트엔드에서 다루면 유출 위험이 크다. |
| 데이터 가공 | 시계열 집계·분석은 서버에서 처리해야 성능·정확도가 보장된다. |

→ 따라서 **백엔드 서버를 반드시 경유**하는 3-Tier 구조로 설계한다.

### 2.2 목표 아키텍처

```
┌─────────────────┐
│  사장님 브라우저  │  ← 대시보드 URL 접속
│  (Dashboard UI) │     자체 로그인 (POS 계정과 분리)
└────────┬────────┘
         │ HTTPS / JSON API
         ▼
┌─────────────────────────────────┐
│        Backend Server           │
│  ┌───────────┐  ┌────────────┐  │
│  │ Auth API  │  │ Data API   │  │
│  └───────────┘  └─────┬──────┘  │
│  ┌──────────────────┐ │         │
│  │ Collector        │ │         │  ← 매일 새벽 자동 실행 (Scheduler)
│  │ (POS 로그인/수집) │ │         │
│  └────────┬─────────┘ │         │
│           ▼           ▼         │
│      ┌──────────────────┐       │
│      │   Database       │       │
│      │ (일별/메뉴별 집계) │       │
│      └──────────────────┘       │
└──────────────┬──────────────────┘
               │ 인증 후 조회
               ▼
        ┌──────────────┐
        │ topint.co.kr │  (POS 원천)
        └──────────────┘
```

### 2.3 POS 데이터 확보 방식 (우선순위)

| 순위 | 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|---|
| 1 | **탑아이앤티 공식 API 제휴** | 안정적, 합법적, 유지보수 용이 | 협의 시간 필요 | **최우선 시도** |
| 2 | **CSV/Excel 정기 내보내기 업로드** | 즉시 가능, 리스크 없음 | 수동 개입 필요 | Phase 1 대안 |
| 3 | 인증된 세션 기반 자동 수집 | 자동화 가능 | 약관 확인 필수, 화면 변경에 취약 | 사전 서면 동의 필수 |

> **REQ-LEGAL-01**: 3번 방식은 (주)탑아이앤티 이용약관 검토 및 매장주 서면 동의 확보 후에만 진행한다. 공모전 제출물이므로 데이터 취득 경로의 적법성을 문서로 남긴다.

## 4. 기능 요구사항

### 4.1 인증 (AUTH)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-AUTH-01 | 대시보드 접속 시 로그인 화면을 최초 표시한다. | 필수 |
| FR-AUTH-02 | ID/PW 입력으로 인증하며, 인증 성공 시 대시보드로 전환한다. | 필수 |
| FR-AUTH-03 | 대시보드 계정은 POS 계정과 **논리적으로 분리**하되, 사장님 편의를 위해 동일한 ID/PW(sodam001)를 초기값으로 사용할 수 있다. | 필수 |
| FR-AUTH-04 | 비밀번호는 평문 저장 금지. 해시(bcrypt 등)로 저장한다. | 필수 |
| FR-AUTH-05 | 인증 실패 5회 시 5분간 로그인을 차단한다. | 권장 |
| FR-AUTH-06 | 세션은 12시간 유지되며, 만료 시 재로그인을 요구한다. | 필수 |
| FR-AUTH-07 | "로그인 상태 유지" 체크박스를 제공한다. (최대 30일) | 선택 |
| FR-AUTH-08 | 로그아웃 기능을 제공한다. | 필수 |

### 4.2 데이터 수집 (COLLECT)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-COL-01 | 매일 정해진 시각(기본 04:00)에 전일 데이터를 자동 수집한다. | 필수 |
| FR-COL-02 | 수집 항목: 일자, 매출액, 결제건수, 객단가, 메뉴별 판매수량/매출, 시간대별 매출, 결제수단, 취소/할인 내역 | 필수 |
| FR-COL-03 | 최초 구축 시 **과거 최소 12개월 데이터를 일괄 수집**한다. (시계열 분석의 전제) | 필수 |
| FR-COL-04 | 수집 실패 시 3회까지 재시도하고, 최종 실패 시 관리자에게 알린다. | 필수 |
| FR-COL-05 | 동일 일자 재수집 시 중복 저장 없이 갱신(UPSERT)한다. | 필수 |
| FR-COL-06 | 수집 이력(일시, 대상기간, 성공/실패, 건수)을 로그로 남긴다. | 필수 |
| FR-COL-07 | 수동 수집(관리자 트리거) 기능을 제공한다. | 권장 |
| FR-COL-08 | CSV/Excel 파일 업로드를 통한 수동 데이터 적재를 지원한다. (대안 경로) | 권장 |

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-DASH-01 | 상단에 핵심 지표 카드(오늘/기간 매출, 결제건수, 객단가, 전기간 대비 증감률)를 표시한다. | 필수 |
| FR-DASH-02 | **일별 매출 시계열 차트**(선/막대)를 표시한다. | 필수 |
| FR-DASH-03 | 기간 선택 필터(오늘 / 최근 7일 / 최근 30일 / 이번 달 / 직접 지정)를 제공한다. | 필수 |
| FR-DASH-04 | **요일별 평균 매출** 비교 차트를 표시한다. | 필수 |
| FR-DASH-05 | **시간대별 매출 히트맵 또는 막대차트**를 표시한다. (피크타임 파악) | 필수 |
| FR-DASH-06 | **메뉴별 매출 TOP 10** 순위표/차트를 표시한다. | 필수 |
| FR-DASH-07 | 메뉴 ABC 분석 결과를 표시한다. | 권장 |
| FR-DASH-08 | 전월/전년 동기 대비 비교 뷰를 제공한다. | 권장 |
| FR-DASH-09 | 데이터 최종 갱신 일시를 화면에 명시한다. | 필수 |
| FR-DASH-10 | 차트 요소에 마우스오버/탭 시 상세 수치 툴팁을 표시한다. | 필수 |
| FR-DASH-11 | 조회 결과를 CSV로 내보낼 수 있다. | 선택 |
| FR-DASH-12 | 데이터가 없는 기간은 "데이터 없음"을 명확히 표시한다. (0으로 오인 금지) | 필수 |

### 4.4 시스템 상태 (SYS)

| ID | 요구사항 | 우선순위 |

## 5. 비기능 요구사항

### 5.1 성능
| ID | 요구사항 |
|---|---|
| NFR-PER-01 | 대시보드 최초 로딩 3초 이내(일반 회선 기준). |
| NFR-PER-02 | 기간 필터 변경 시 차트 갱신 1초 이내. |
| NFR-PER-03 | 12개월 데이터 조회 시에도 API 응답 2초 이내. (사전 집계 테이블 활용) |

### 5.2 보안
| ID | 요구사항 |
|---|---|
| NFR-SEC-01 | 전 구간 HTTPS 적용. |
| NFR-SEC-02 | POS 계정 정보는 서버 환경변수 또는 시크릿 매니저에 암호화 저장. 소스코드·Git 저장소에 절대 포함하지 않는다. |
| NFR-SEC-03 | 프론트엔드 코드·네트워크 응답에 POS 계정 정보가 노출되지 않아야 한다. |
| NFR-SEC-04 | API는 세션/JWT 인증 없이는 데이터를 반환하지 않는다. |
| NFR-SEC-05 | SQL Injection, XSS 방어를 적용한다. (파라미터 바인딩, 출력 이스케이프) |
| NFR-SEC-06 | 접근 로그를 최소 90일 보관한다. |
| NFR-SEC-07 | **현재 공유된 계정(`sodam001` / 비밀번호는 본 문서에 기재하지 않음)은 개발 착수 전 비밀번호를 변경하고, 변경된 값은 별도 보안 채널로 전달한다.** 변경된 값은 `.env`에만 보관한다. |

### 5.3 가용성·운영
| ID | 요구사항 |
|---|---|
| NFR-OPS-01 | 서비스 가용률 목표 99% (월 기준). |
| NFR-OPS-02 | DB는 일 1회 백업한다. |
| NFR-OPS-03 | 수집 실패 시 알림(이메일 또는 메신저)을 발송한다. |

### 5.4 호환성·사용성
| ID | 요구사항 |
|---|---|

| NFR-USE-02 | **모바일 반응형 필수.** 사장님은 매장에서 휴대폰으로 볼 가능성이 높다. |
| NFR-USE-03 | 전문 용어 최소화. 숫자는 천단위 구분기호와 "원" 단위 병기. |

| NFR-USE-05 | 폰트 최소 14px, 핵심 지표는 24px 이상. |

| | 판매수량 | ✅ | |

### 6.2 데이터 품질 규칙
- DQ-01: 매출액이 음수인 레코드는 취소 건으로 분류하여 별도 관리한다.
- DQ-02: 휴무일은 `is_closed = true`로 기록하여 0원 매출과 구분한다.
- DQ-03: 일별 매출 합계와 메뉴별 매출 합계의 오차가 1% 초과 시 경고 로그를 남긴다.
- DQ-04: 결측 일자는 대시보드에서 보간하지 않고 결측으로 표시한다.

### 6.3 보관 정책
- 원본 수집 데이터(raw): 무기한 보관
- 집계 테이블: 무기한 보관
- 개인정보(고객 식별정보): **수집하지 않음**

## 7. 제약사항 및 가정

### 7.1 제약사항
| ID | 내용 |
|---|---|
| CON-01 | POS 데이터 접근은 (주)탑아이앤티 정책에 종속된다. |
| CON-02 | 정적 HTML만으로는 구현 불가하며 백엔드 호스팅 비용이 발생한다. |
| CON-03 | POS 화면 구조 변경 시 수집기 수정이 필요할 수 있다. |
| CON-04 | 공모전 일정에 따른 개발 기간 제약이 있다. |

### 7.2 가정
| ID | 내용 |
|---|---|
| ASM-01 | POS에서 최소 12개월 이상의 과거 데이터 조회가 가능하다. |
| ASM-02 | 데이터는 일 1회 갱신으로 충분하다. (실시간 요구 없음) |
| ASM-03 | 사용자는 사장님 1인 + 매니저 소수로, 동시접속 부하는 낮다. |
| ASM-04 | 마곡점 단일 매장 기준이며, 다점포 확장은 차기 과제로 둔다. |

## 8. Phase 1 완료 기준 (Acceptance Criteria)

아래 항목이 모두 충족되면 Phase 1을 완료로 본다.

- [ ] AC-01: 대시보드 URL 접속 시 로그인 화면이 정상 표시된다.
